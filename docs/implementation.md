# Implementation and compatibility record

Updated 10 September 2026. Version `0.2.0-alpha.1`, branch `feat/workers-foundation`, [draft PR #1](https://github.com/mitchell-johnson/Hyena/pull/1). The baseline is Wildebeest `b056670a7204bc4d852c8a0cda9a3c9e39f8a0e1`. The new runtime uses fresh D1 migrations; the old application is retained as reference only.

The implementation now spans all C01–C32 areas in the [build plan](build-plan.md). This statement means there is working implementation in each area, not that every behavior has been proved equivalent. The target is [Mastodon v4.7.1](https://github.com/mastodon/mastodon/tree/v4.7.1), commit `bc19d30b90403d9d058da301bcd7fafcc03fbf92`, API level 11. The instance retains `api_versions.mastodon: 0` and a false compatibility-verification flag until the external conformance gates pass. It does not claim a completed production certification.

## Federation

Fedify 2.3.6 provides the protocol builder, WebFinger/NodeInfo, JSON-LD vocabulary, HTTP signatures, signed document loading and delivery serialization. Both RSA and Ed25519 identity keys are persisted encrypted. Its D1-backed key/value and message interfaces use the same durable database as social mutations. Native queue messages containing private signing material are encrypted before storage. Cloudflare Workers key bindings are not exposed in the client.

Incoming activity ownership is checked against actor/object identity; local identities cannot be impersonated by a remote actor. Follow/Accept/Reject, Create/Update/Delete, Like/Undo, Announce, Block, Move, Flag and featured Add/Remove have handlers. Tombstones prevent resurrection. HTML is sanitized before storage. Remote attachment URLs are retained; Hyena does not run an unbounded remote-media cache or transcode every incoming attachment.

Collections use the current FeatureRequest/FeatureAuthorization extension as raw JSON-LD where the generated vocabulary does not supply its new types. Quotes use the corresponding consent/authorization objects. Authorization identities and subject/object relationships are checked before displaying accepted interactions. These extension paths require two-server interoperability verification, not just a successful vocabulary round trip.

## Delivery and consistency

- D1 is authoritative. A content mutation and its job intent commit together. A Queue message holds only `{version: 1, id}`. The scheduled sweep recovers missed publishes, duplicates and expired leases.
- Consumers use five-minute leases with a bounded heartbeat. Ordering keys and D1 locks serialize related deliveries, with insertion order resolving jobs sharing a timestamp. A post edited before its first fan-out still queues Create before Update.
- Transient failures use exponential jittered retry up to six hours between attempts. The seven-day/100-attempt terminal bound starts at the first execution, so a post scheduled months ahead retains its retry window. Poison jobs are durable, visible and retryable by an administrator.
- Delivery is at least once. Stable activity IDs, inbox receipt checks, mutation guards and delivery receipts make retries safe; the implementation does not promise exactly-once remote effects.
- Queue work rechecks current followers, blocked actors/domains, suspension, deletion and status audiences after waiting. Per-recipient inboxes avoid silently broadening a private audience through a shared inbox.
- Primary D1 reads serve authorization and read-after-write behavior. Read replicas and additional caches are unnecessary for the selected personal-instance baseline. No eventually consistent authentication cache is introduced.
- SQLite DOs hibernate WebSockets. Persistent state is not a guarantee that JavaScript stays running. SSE requests have a different cost profile; WebSocket is the preferred client transport.
- Maintenance mode pauses HTTP mutations and durable processing. D1/R2 recovery scripts keep secrets separate and require isolated empty restore targets. Live recovery remains an operator acceptance test.

## Media contract and price controls

Local animated media, MP4 and MP3 are probed before transformation; duration must be below 60 seconds. Advertised input limits are enforced by bytes, dimensions, frame budget, codec and duration. GIF/WebP/APNG animation control data is parsed rather than treating an animated image as a single frame. Animated pixel budgets stay below the Images threshold that can bypass transformation, because bypassing would retain metadata.

Images become WebP derivatives; video becomes H.264/AAC MP4 with a frame preview. MP3 packets are remuxed without tags without a decoding/transcoding service. The originals and temporary thumbnails are deleted after successful processing. Attached media descriptions are edited through the status API, matching the reference media controller's detached-media rule. R2 stays private; only processed capability paths are served.

Costs are limited by per-month uploaded-byte, image-operation and media-second budgets and bounded retries/concurrency. Budgets are atomic and avoid double charging one logical operation in application accounting. They do not measure all Cloudflare charges, and a provider retry can still produce a provider charge. Rate-limited auth, bounded uploads, small local account counts, narrow queues and no automatic remote-media caching control the personal-instance footprint.

Current platform references, checked 10 September 2026: [Images binding](https://developers.cloudflare.com/images/optimization/binding/), [Images limits](https://developers.cloudflare.com/images/get-started/limits/), [Media binding](https://developers.cloudflare.com/stream/transform-videos/bindings/), [Media transformations](https://developers.cloudflare.com/stream/transform-videos/), [DO rules](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/), [Queues pricing](https://developers.cloudflare.com/queues/platform/pricing/).

## Validation evidence

Final local checkpoint: **45 workerd integration tests across seven files, one Node/SQLite backup round-trip test, TypeScript checks and a Wrangler 4.130.0 deployment dry-run pass**. The generated Worker measures 8,183.45 KiB uncompressed / 1,126.42 KiB gzip. The 300-route reference inventory is included in that test run. Operational scripts pass Node syntax checks, and provisioning plan mode runs without account changes.

The repository contains tests in actual workerd with local D1, R2 and SQLite DOs. They cover OAuth concurrency/replay/scopes, status and media attachment races, duration/codec parsing, scheduling, polls, audiences, graph changes, filters, notifications, collections, registration, TOTP/recovery codes, CIDRs, budgets, encrypted queue storage/order/retry, current-audience rechecks, cryptographic signature/push round trips and the pinned route inventory. Remote transformations and transport calls are explicitly replaced; those service implementations are not certified by a test double.

A separate Node/SQLite snapshot test exercises 64-bit integer preservation, blobs, SQL-shaped text, negative row IDs, embedded null characters and large values that need bounded restore statements. The browser smoke exercised setup, login, creating a post, 16 principal views, settings tabs, a WebSocket upgrade and desktop/390-pixel layouts in Chromium 152. It reported zero JavaScript errors, zero HTTP 5xx responses and no page horizontal overflow. The checked-in local-dev/browser scripts also passed the final rerun, including health/readiness. It did not test a native mobile app, a physical passkey authenticator, browser push delivery or Cloudflare's remote media services.

The browser run found and fixed `Referrer-Policy: no-referrer` suppressing the Origin needed for HTML form CSRF checks. The runtime now uses `same-origin`. Server-log review also caught reserved WebSocket close codes being echoed on ordinary browser disconnects; the final run has no uncaught close-code errors. The initial protocol test found and fixed the partial unique-index conflict target in remote status ingestion. Additional boundary tests cover cached content after domain moderation, Create-before-Update, old scheduled jobs, email confirmation, maintenance, actual link-trend history and owner-only relationship-loss CSV exports. Remote reports produce moderator notifications, including their payloads in grouped responses.

An npm production audit initially found the OpenTelemetry baggage allocation advisory. Pinned 2.8.0 overrides remove the affected dependency chain without downgrading Fedify. The subsequent `npm audit --omit=dev` reported zero advisories. See [GHSA-8988-4f7v-96qf](https://github.com/advisories/GHSA-8988-4f7v-96qf); this audit is not a full security assessment.

## Explicit release limits

1. **No live deployment or real app certification.** Provisioned Cloudflare services, a stable DNS identity, real native apps, a remote Mastodon 4.7.1 peer and service delivery endpoints are needed for the external checks below. There is no claim of complete Mastodon equivalence.
2. **Media formats are an instance policy.** Arbitrary MOV/HEVC/WebM/Ogg/AVIF are not accepted merely because they last under a minute. The cheap baseline advertises only implemented formats. Media binding beta availability/output/billing must be checked in the target account.
3. **Private media is capability based.** A copied processed URL remains usable while its record is available. Remote media is fetched by clients from its source. This is not end-to-end encryption or per-download OAuth access control.
4. **Search uses bounded SQL search.** It does not provide Elasticsearch's entire query language, ranking or indexing behavior. Remote resolution, account/tag/status search and API result shapes are implemented.
5. **Some reference behavior depends on absent configuration/data.** Closed registration, no translation service, no donation campaign, no legacy identity proofs and an inactive annual campaign legitimately produce disabled or empty responses. Annual-report schema 2 follows the pinned reference's annual aggregate and null optional ranking fields.
6. **User experience and ecosystem breadth need acceptance.** Browser smoke coverage is not a full accessibility audit, all-screen interaction coverage, all-platform WebAuthn test, full streaming replay equivalence, or a native app matrix.
7. **Recovery requires a drill.** Snapshot creation/verification/empty-target restore code exists, including R2 metadata. No live Cloudflare backup, import, Time Travel, key restore, domain cutover or disaster replay was executed. The code assumes a fresh deployment and does not convert a live historical Wildebeest identity/database in place.
8. **Personal-instance scale is intentional.** Fan-out, queries and local account limits favor small installations. Costs are estimates, not a measured load profile. Large-instance distribution, unlimited retention and every moderation lifecycle edge case have not been demonstrated.

## External acceptance checklist

Use this as a release gate, not an unimplemented-feature promise. Store actual results and versions, and keep API level 0 until failures are resolved.

- Provision a fresh Workers Paid account configuration, DNS/custom domain, bindings and secrets. Apply all migrations and verify actor/key stability across redeploys.
- Connect the current official Mastodon mobile apps plus at least two independent clients. Exercise dynamic registration, consent, callback, token revocation, refresh/relaunch, composing, all supported media, edits, polls, schedules, follows, notifications, pagination, quotes, collections and logout. Check callback behavior on iOS/Android, not only desktop HTTP requests.
- Pair with the pinned Mastodon peer. Exercise open/locked follow approval, private/direct posts and replies, mentions, favourites/boosts/undo, edit/delete, quotes/revocation, featured collections/consent, signed fetch, account move and moderation in both directions. Confirm destination logs and user-visible results.
- Submit the media corpus to the real Images/Media bindings. Inspect duration, dimensions, codecs, orientation, animation, metadata stripping, thumbnails and provider billing. Test failures and at-limit inputs.
- Register real browser/mobile push subscriptions and hardware/platform passkeys. Send transactional confirmation/reset/change email through the configured sender domain. Test revoked endpoints and tokens.
- Run a measured month-equivalent load/retry test; capture CPU, D1 rows/bytes, R2 storage/operations, Queue operations, DO active time and transformations. Confirm budget rejection and recovery behavior.
- Back up in maintenance, restore to empty resources with the same origin/keys, validate exact IDs/foreign keys/R2 bytes and metadata, then replay jobs against a test peer. Validate upgrade and rollback without resurrecting deleted content or losing revocations.
